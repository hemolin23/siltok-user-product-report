WHY USERS DROP

精准用户仍不转化的原因

  1. 认知不成立

    不理解端侧 AI，无法迅速把技术概念换算成自己的收益。

  2. 切换动机不足

    云服务已满足需求，没有强烈成本、隐私或稳定性痛点。

  3. 信任与协议摩擦

    加微信后很快进入身份核验、NDA 和合作协议，决策成本陡增。

  4. 执行成本过高

    排设备、约时间、学操作、跑任务、整理反馈都需要用户额外投入。

  5. 需求时点不匹配

    “身份精准”不等于“此刻正在采购或切换工具”。

  6. 已读不回

    价值说明较长、步骤较多，且首轮缺少一个可立即获得的结果。

02

FEEDBACK & QUALITY

用户案例、质量、Bug 与建议

现有高质量反馈数量不多，但已出现高度一致的问题簇。

A级 · 可复现

云端 5090 vs 本地 4060

同模型同提示词下，云端 5 秒约 10 分钟、本地约 50 分钟；云端更快但画质反而更差，1080P 观感接近 480P，并有频繁断连。

结论：问题不只是算力，指向模型版本、渲染链路、输出标注与任务持久化。
A级 · 业务决策

电商 + 短剧团队访谈

电商需要 API、飞书数据源和批量替换；短剧质量优先。5070 长尾可到约 40 分钟，单机约 3 个并发用户。

结论：团队场景优先需要官方 API、云算力与队列，而不是先堆复杂节点界面。
A级 · 技术建议

倪海敬 · 独立创作者

图像工作流基本可用；文生视频模糊、人脸崩，图生视频相对可用。给出了分阶段提示词和“插值扩展 sigma”节点建议。

价值：反馈包含任务表现、对照判断和可操作的工作流参数。

PROFESSIONAL CG DIRECTOR

专业 CG 导演：海外短剧与游戏视频

这是你新增的专家观察，属于创作质量评估。现阶段保留为定性反馈，等原片、对照片和镜头参数关联后再升级为可复测结论。

海外短剧 · 10 秒

可取之处：景深自然，人物微表情较好，眨眼尤其明显。

不足：AI 感重、缺少影调，视听语言单一。

对照方式：用你做的影调版本并排看同一镜头，逐项比较光比、色彩层次、镜头调度与情绪表达。
游戏视频

未达到导演预期：动作缺少动画规律，人物手指出现崩坏。

对照方式：用你制作的分镜，逐镜核对动作起承转合、关键姿态、运动连续性和手部结构。
给产品 / 技术的任务把“好看”拆成可讨论的镜头语言：影调、人物表演、动画规律、手部结构；测试时保留原片、参考分镜、提示词、模型、种子和输出版本。
BUG / RELIABILITY

确定性故障

断连、模型不可用后置提示、任务失败、长任务无法恢复、批量运行缺少持久化。

优先级：P0，先保证任务不丢。
QUALITY

结果质量

人脸模糊、肢体结构、元素融合、颜色漂移、小字错误、音频回声、1080P 名不副实。

优先级：P0，建立真实输出验收。
PERFORMANCE

速度与吞吐

5070 长尾明显、15 秒 720P 可达 60 分钟；单机多人场景会排队。

优先级：P1，按任务公布 P50 / P90。
FEATURE

功能建议

官方 API、批量队列、进度通知、资产库、项目管理、参考图角色、自动拼接和自定义工作流。

优先级：P1/P2，按首发场景收敛。
WHY SO FEW

为什么高质量反馈不多？

  1. 样本没有走到真实任务多数用户停在微信、协议或首次测试之前。
  2. 反馈成本高测试、复现、截图、记录参数和写建议都需要额外时间。
  3. 产品问题过早暴露断连、排队和环境摩擦把反馈挤压成“能不能跑”，难以进入专业质量讨论。
  4. 采集工具分散表单、聊天、会议、共享文档和测试表之间缺少任务 ID 关联。
  5. 任务过宽让用户自由探索容易产生描述性意见，不容易形成可验收问题。

反馈进入研发的最低标准

  1. 可追溯用户、任务 ID、成片或原始记录
  2. 有影响返工、时间、成本或交付后果
  3. 可复现设备、版本、输入、参数与日志
  4. 可验收修复后的量化通过标准

POINT OF VIEW

我对产品与现状的判断

基于触达、测试、会议和反馈形成的阶段性判断。

01

产品不是“端侧硬件”，而是 AI 生产基础设施

真正被需要的是工作流、任务队列、资产、模型、恢复机制和可交付结果；设备只是承载方式。

02

端侧价值只在特定条件下成立

高频使用、成本敏感、数据隐私、可控工作流和稳定复用时，本地有优势；低频用户用云更省事。

03

团队用户更需要“云 + API”，而不是单机共享

单机约 3 并发，10 人团队会排队；电商和短剧需要批量、队列、API 和云算力。

04

速度领先不能掩盖质量与稳定性

云端 5090 比本地 4060 快约 5 倍，但同任务质量更差；如果更快地产出不可用结果，商业价值仍为负。

05

用户运营正在承担产品教育和人工调度系统

当前大量时间花在解释端侧 AI、分设备、约测试、追反馈。若产品不降低这些摩擦，运营规模越大，人工负担越重。

06

下一阶段不应继续只扩线索池

优先把 3 个真实案例做深：明确原方案、输入、首次可用率、总耗时、限制和是否继续使用。

CAPABILITY & PERFORMANCE

产品功能性与性能的区别

“做得到”不等于“做得好、做得快、持续做得到”。

A · FUNCTION

功能性

有没有、能不能完成

例：文生视频、图生视频、工作流导入、API、资产管理
B · QUALITY

质量

结果能不能交付

例：人脸、动作、文字、声音、清晰度、提示词遵循
C · PERFORMANCE

性能

完成一次需要多久

例：冷启动、P50、P90、单位时长生成时间、吞吐
D · RELIABILITY

稳定性

能不能持续完成

例：失败率、断线恢复、重试、长任务、任务不丢
E · CAPACITY

容量

能服务多少人

例：并发用户、排队时长、设备调度、资源隔离
F · USABILITY

可用性

用户是否会用

例：能力说明、参数保留、简单/专业模式、错误提示

# 产品打磨建议

1. **用户自定义模型与工作流。**支持用户自带模型或工作流，提供 ComfyUI 定制化安装（可由 Agent 提问引导完成选型与安装），满足不同用户偏好的私有方法。
2. **开放多模型选择。**AStar、SOL、Lunna、MiniMax 等按需切换，避免锁死在单一模型上。
3. **质量规格透明。**明示真实分辨率、码率与采样参数，不做「标 1080p、出 480p」式的名实不符。
4. **连接稳定性优先。**掉线是当前第一优先级，解决后批量与长任务体验会整体变好。
5. **批量任务管理。**任务队列、进度展示、断点续跑与完成通知。
6. **验收标准化。**引入「动态视力验收」等可复现验收流程，作为成片交付基准。
7. **采纳四步加速方案。**本地已验证效果，可作为云端默认或可选的加速项。
8. **由 Codex 接管云端尝试。**建议开放 Agent（Codex）接管云端任务的试点：由 Agent 自动调参与复现，争取达到本地同等质量。

# 自动化与模型评测方向

- **Agent 接管云端：**由 Codex、豆包等 Agent 自动完成安装、跑任务与验收，降低人工盯守成本。已提出具体尝试：由 Codex 接管云端任务，自动调参并复现，争取达到本地同等质量。
- **定制化安装流程：**Agent 提问 → 用户选择 → 定制化安装 ComfyUI 与合适的模型。
- **模型评测自动化：**统一指令＋多模型并行＋自动对比质量、耗时与成本。
- **全自动候选方案：**若 Lunna 动态视力达标且成本低，可支撑「输入脚本 → 自动生成 → 自动验收 → 出片」的全自动流水线。
- **多 Agent 协作已验证：**GPT 产出交接文档 → 豆包/Codex 按指令执行 → GPT 验收。可在云端复用到「任务调度 → 执行 → 验收」闭环。

新人照着做的完整步骤
